```
release-note:changed
resource/anyscale_cloud: A refresh or destroy that gets HTTP 403 for the cloud now treats it as deleted, with a warning, instead of failing, since the API can answer 403 rather than 404 for a deleted cloud. If the token lost access instead, a refresh leads to a duplicate on the next apply unless access is restored, and a destroy leaves the cloud outside Terraform; check it in the Anyscale console.
resource/anyscale_cloud_resource: A refresh or destroy that gets HTTP 403 for the cloud resource or its cloud now treats it as deleted, with a warning, instead of failing, since the API can answer 403 rather than 404 for a deleted cloud. If the token lost access instead, a refresh leads to a duplicate on the next apply unless access is restored, and a destroy leaves the cloud resource outside Terraform; check it in the Anyscale console.
resource/anyscale_project: A refresh or destroy that gets HTTP 403 for the project now treats it as deleted, with a warning, instead of failing, since the API can answer 403 rather than 404 for a deleted project. A destroy still retries a 403 on a just-created project first, and a 403 for running jobs or services is still an error. If the token lost access instead, a refresh leads to a duplicate on the next apply unless access is restored, and a destroy leaves the project outside Terraform; check it in the Anyscale console.
resource/anyscale_service: A refresh or destroy that gets HTTP 403 for the service, including while waiting for it to terminate, now treats it as deleted, with a warning, instead of failing, since the API can answer 403 rather than 404 for a deleted service. A service removed while terminating (404 or 403) no longer fails the destroy. If the token lost access instead, a refresh leads to a duplicate on the next apply unless access is restored, and a destroy leaves the service outside Terraform; check it in the Anyscale console.
```
