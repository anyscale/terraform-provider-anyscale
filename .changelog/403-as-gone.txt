release-note:changed
resource/anyscale_cloud: A refresh or destroy that gets HTTP 403 for the cloud now treats it as deleted, with a warning, instead of failing; the API answers 403 rather than 404 for a deleted cloud. If the token lost access instead, restore access before the next apply or it creates a duplicate.
resource/anyscale_cloud_resource: A refresh or destroy that gets HTTP 403 for the cloud resource or its cloud now treats it as deleted, with a warning, instead of failing; the API answers 403 rather than 404 for a deleted cloud. If the token lost access instead, restore access before the next apply or it creates a duplicate.
resource/anyscale_project: A refresh or destroy that gets HTTP 403 for the project now treats it as deleted, with a warning, instead of failing; the API answers 403 rather than 404 for a deleted project. A destroy still retries a 403 on a just-created project first, and a 403 for running jobs or services is still an error. If the token lost access instead, restore access before the next apply or it creates a duplicate.
resource/anyscale_service: A refresh or destroy that gets HTTP 403 for the service now treats it as deleted, with a warning, instead of failing; the API answers 403 rather than 404 for a deleted service. If the token lost access instead, restore access before the next apply or it creates a duplicate.
