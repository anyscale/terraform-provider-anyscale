```
release-note:changed
resource/anyscale_cloud / anyscale_cloud_resource: `aws_config.subnet_ids_to_az` changes now update the cloud in place instead of replacing it, using the same API route as `anyscale cloud update`.
```
```
release-note:changed
resource/anyscale_cloud / anyscale_cloud_resource: subnet changes made outside Terraform (for example with the Anyscale CLI) now show in `terraform plan`, and apply reverts them in place. `ignore_changes` on subnets can be dropped once the configuration matches the live cloud.
```
```
release-note:breaking-change
resource/anyscale_cloud / anyscale_cloud_resource: changing the set of subnets in `aws_config.subnet_ids` is now an error at plan time instead of a replacement. Anyscale derives the availability zones itself and live testing showed the backend can pair them with the wrong subnets; rewrite the setting as `subnet_ids_to_az` with each subnet's zone and the change then applies in place.
```
